# 游戏测试用例生成技能

## 触发场景

当用户需要根据游戏系统策划文档、需求文档、Excel/PDF/Word/Markdown 内容生成测试用例、QA 用例、功能覆盖点或测试用例 Excel 时，使用本技能。

## 目标产出

根据游戏系统策划文档，提取功能模块、规则逻辑、配置表、界面交互、数值规则和异常边界，按标准化 11 列模板批量生成结构化测试用例，并在需要时输出带样式的 Excel 文件。

## 工作流程

1. **解析策划文档**
   - Excel：用 pandas/openpyxl 读取所有 sheet，逐 sheet 提取内容。
   - PDF/Word/Markdown：提取标题、表格、规则说明、配置字段、流程描述。
   - NaN 值处理必须使用 `str(x) if pd.notna(x) else ''`，不要直接 `astype(str)`。
2. **模块划分**
   - 按系统架构划分一级测试模块。
   - 为每个模块分配 2-4 个大写字母缩写，如兵营=BAR、医院=HSP、校场=SCH、士兵=SOL、英雄带兵=HERO。
3. **功能点枚举**
   - 列出每个模块下所有二级功能点。
   - 覆盖入口、展示、操作、规则校验、数值计算、奖励、异常处理、日志/记录等。
4. **用例设计**
   - 每个功能点至少包含正常场景。
   - 核心功能点必须包含异常场景和边界场景。
   - 根据系统类型补充专项测试维度。
5. **去重校验**
   - 生成后必须去除重复或高度相似用例。
   - 判定标准：用例标题相同，或“前置条件+操作步骤+预期结果”三者同时高度相似（相似度 >80%）。
   - 保留覆盖更全面的版本，或合并为一条更完整用例。
6. **格式化输出**
   - 默认输出 Markdown 表格或结构化列表。
   - 用户要求 Excel 时，用 openpyxl 生成 `.xlsx` 文件并设置样式。

## 标准 11 列模板

| 列名 | 说明 | 格式要求 |
|------|------|----------|
| 用例ID | 唯一标识 | TC-{模块缩写}-{三位序号}，如 TC-BAR-001 |
| 测试模块 | 功能大模块 | 对应系统一级模块 |
| 功能点 | 具体功能点 | 模块下二级功能点 |
| 场景类型 | 测试场景分类 | 正常场景 / 异常场景 / 边界场景 |
| 用例标题 | 简明描述 | 一句话概括测试目标，动宾结构 |
| 前置条件 | 执行前提 | 执行该用例前需要满足的条件 |
| 操作步骤 | 具体步骤 | 多步骤换行分隔，编号列出 |
| 预期结果 | 期望输出 | 与操作步骤对应，多条目换行分隔 |
| 优先级 | 重要程度 | 高 / 中 / 低 |
| 测试类型 | 测试分类 | 功能测试 / 数值测试 / UI测试 / 性能测试 / 异常测试 / 边界测试 |
| 执行状态 | 执行结果 | 留空待填 |

## 编号规则

- 前缀固定为 `TC-`。
- 模块缩写为 2-4 个大写字母。
- 序号为三位数字，从 001 开始递增。
- 示例：`TC-BAR-001`、`TC-ACT-012`、`TC-GVG-026`。

## 场景类型定义

- **正常场景**：符合业务逻辑的主流程、标准流程、主要分支。
- **异常场景**：非法输入、网络异常、资源不足、操作顺序错误、越权访问、反向操作。
- **边界场景**：最大值、最小值、临界值、0 值、空值、最后一秒、首日/末日、上限/下限。

## 测试类型定义

- **功能测试**：验证功能逻辑正确性。
- **数值测试**：验证资源消耗、产出、概率、权重、公式、等级梯度。
- **UI测试**：验证界面显示、布局、文案、红点、弹窗、状态刷新。
- **性能测试**：验证大量数据、长时间运行、并发、帧率、加载耗时。
- **异常测试**：验证弱网、断线、重连、杀进程、服务器异常、容错。
- **边界测试**：验证边界值、极限条件、周期切换、次数上限。

## 优先级定义

- **高**：核心功能、主流程、高风险点、付费点、奖励、排行、结算、数据一致性。
- **中**：重要分支、常见操作、一般功能、常见异常。
- **低**：低频操作、边缘显示、非核心体验项。

## 通用设计原则

### 完整覆盖

- 覆盖策划文档中的所有模块和功能点。
- 每个功能点至少一条正常场景用例。
- 关键功能点补充异常、边界、弱网、并发、数据一致性用例。

### 正常场景要求

- 操作流程符合策划文档标准流程。
- 使用合法参数和正常范围数据。
- 覆盖主干路径和主要分支。
- 前端界面、文案、布局、状态变化符合设计。

### 异常场景要求

- 非法输入：格式错误、特殊字符、内容违规。
- 资源不足：货币、道具、次数、等级、权限不足。
- 唯一性校验：重复名称、重复领取、重复提交。
- 操作顺序错误：跳过关键步骤、反向操作、越级访问。
- 网络异常：弱网、断网、超时、重试、断线重连、杀进程。

### 数值专项要求

- 概率分布与公示一致。
- 资源消耗与产出一致。
- 等级、品质、星级、战力、属性梯度正确。
- 公式计算正确，前后端展示一致。
- 弱网/并发下不出现收支不等。

### 时间专项要求

- 倒计时准确，状态变化及时。
- 压后台、断线重连、离线期间计时正确。
- 跨天、跨周、跨赛季、跨活动周期重置正确。
- 修改系统时间不能绕过服务端校验。

## 所有游戏系统必测 6 个维度

### 维度1：多玩家状态矩阵

关键数据节点（奖励发放、数据结算、状态变更、周期重置、开启/结束）必须按玩家状态组合展开：

- 未参与/未触达玩家 × 在线等待状态变更
- 未参与/未触达玩家 × 离线等待状态变更
- 已参与/已触达玩家 × 在线等待状态变更
- 已参与/已触达玩家 × 离线等待状态变更
- 已参与/已触达玩家 × 在系统界面内等待状态变更

每种组合验证：

1. 数据变更是否正确。
2. 补发邮件是否完整且正确。
3. 状态切换是否实时生效。
4. 数据记录是否准确。

有周期/轮次系统需额外覆盖跨期：上一期参与玩家一直离线，下一期开启时奖励补发、旧数据清理、新一期可用性、跨期继承是否正确。

### 维度2：账号切换与数据隔离

- 切换账号后系统数据互不干扰。
- 已领取奖励、已完成操作互不影响。
- 不显示上一账号缓存残留。
- 进度、积分、排行榜、配置刷新正确。
- 连续切换账号后数据一致。

### 维度3：排行榜容灾处理

适用于排行榜、榜单、排名系统：

- 异常玩家被 GM 删除后排名正确重算。
- 被删除玩家奖励不再发放，且不影响其他玩家。
- 界面无空位、错位、序号断裂。
- 其他玩家排名变化实时生效。
- 批量删除异常玩家后数据一致。
- 被删除玩家重新登录后不重新上榜或显示为已清除。

### 维度4：跨服数据互通

适用于跨服活动、跨服竞技场、跨服交易等：

- 多服积分、排名、进度同步正确。
- 玩家确实属于跨服分组。
- 数据记录中的玩家归属服正确。
- 跨服分组内单服宕机时，其他分组不受影响。
- 宕机服恢复后玩家数据不丢失，可继续参与。
- 跨服结算时宕机服数据有延迟结算或补偿机制。

### 维度5：服务端操作数据免疫

停服重启、宕机、合服、玩家迁服不应破坏玩家系统数据：

- 倒计时暂停/恢复或补算正确。
- 已领取奖励、已完成操作记录保留。
- 未完成进度、队列、积分保留。
- 合服后数据正确合并，排行榜正确处理。
- 迁服后原服数据正确转移，新服数据正确继承。

### 维度6：奖励发放专项

- 在线玩家即时发奖。
- 离线玩家邮件补发。
- 大量玩家同时领奖并发正确。
- 发放前后几秒边界领奖正确。
- 多次点击、并发请求、网络重试、断线重连、多次登录不可重复发奖。
- 补发邮件内容、数量、时效正确。

## 系统类型专项参考

### 大型养成系统（城建/英雄/装备/科技）

重点覆盖：

- 建造/研究/训练倒计时，离线和断线重连后计时一致。
- 升级前后属性加成正确。
- 多队列并行时资源扣除和时间独立计算。
- 抽卡概率与公示一致，保底准确触发，跨池继承正确。
- 强化/升级资源消耗具备原子性。
- 科技树分支解锁和前置条件正确。
- 养成属性在战斗、排行榜、展示界面一致。
- 修改设备时间不能加速建造/研究。

### 活动系统（限时/周期/赛季/七日任务）

重点覆盖：

- 活动开始/结束时间准确，含时区、跨天、最后一秒。
- 开启条件正确：开服天数、等级、注册天数、前置任务。
- 奖励领取幂等，不可重复领取。
- 红点逻辑正确：可领亮、领完灭、条件不足不亮。
- 在线跨天和离线跨天刷新逻辑分别验证。
- 活动结算、排名、积分、奖励发放正确。
- 活动期间重启、热更配置、弱网领奖不丢数据不重复发奖。

### 跨服活动 / 跨服系统

重点覆盖：

- 匹配公平性：战力、等级、段位、分组。
- 跨服数据同步延迟与一致性。
- 断线重连后回归战斗或活动。
- 多服务器并发稳定性。
- 跨服排行榜实时刷新。
- 跨服战斗结算结果同步回原服。
- 合服、节点故障、数据库主从切换、网络分区下数据不丢失。

### 大地图 / 世界地图

重点覆盖：

- 自由行军移动、方向调整、指令撤销流畅正确。
- 相遇即战、地形影响、天气影响正确。
- 攻城战宣战、集结、攻城、占领多阶段流程正确。
- 千人同屏渲染性能。
- 资源点采集/争夺并发冲突处理。
- 行军中杀进程重连后位置和状态正确。

### 联盟系统

重点覆盖：

- 联盟创建条件：资源、等级、冷却时间。
- 成员上限随等级或城池占领扩展正确。
- 会长、副会长、指挥、成员权限边界清晰。
- 会长不活跃自动转让逻辑正确。
- 联盟科技、商店、贡献、援助、集结、邮件、公告、礼物。
- 退出/解散后贡献、奖励、数据归属正确。
- 多人同时申请、加入、退出时状态一致。

### GVG 玩法（公会战/联盟战/领地争夺）

重点覆盖：

- 报名、备战、占城、结算多阶段时间切换。
- 报名竞标和准入条件。
- 雕像摧毁、5 秒重生、积分归属。
- BOSS 刷新和击杀归属。
- 营地复活点和复活冷却。
- 人数差异血量补偿。
- GVG 断线重连和服务器崩溃恢复。
- 个人/公会/赛季奖励结算。

## 传统专项测试维度

### 性能测试

关注 FPS、CPU、GPU、内存、DrawCall、Batches、Triangles、加载时长、发热耗电、网络延迟、包体大小。

常用基准：

- FPS：优秀 60 帧且波动 ≤5；良好 45-60；可接受 30-45。
- CPU：优秀 ≤40%；良好 ≤60%；可接受 ≤80%。
- GPU：优秀 ≤50%；良好 ≤70%；可接受 ≤85%。
- 内存：安卓优秀 ≤300MB，良好 ≤512MB；iOS 优秀 ≤250MB，良好 ≤400MB。
- DrawCall：优秀 <100，良好 <200，可接受 <400。
- 加载：冷启动 ≤5s，场景切换 ≤3s。
- 网络：延迟 ≤100ms，丢包 ≤1%。

### 兼容测试

覆盖：

- 高中低端和超低端机型。
- Android、iOS、HarmonyOS 版本。
- 720P-4K 分辨率和 DPI。
- 刘海屏、挖孔屏、折叠屏、横竖屏。
- MIUI、EMUI、ColorOS、One UI 等 ROM 差异。
- Mali、Adreno、PowerVR 等 GPU。
- 90Hz/120Hz 高刷新率。
- 多点触控、全面屏手势、陀螺仪。

通过标准：适配不通过机型用户占比 ≤1%，机型数量占比 ≤3%，Crash 率 ≤1%。

### 安全测试

重点覆盖：

- 协议加密强度和动态密钥。
- 内存修改防护。
- 加速器防护，服务端速度校验。
- 自动化脚本和挂机检测。
- 服务端二次确认、范围验证、时间验证。
- SQL 注入、重放攻击、路径遍历、SSRF、命令注入。
- 客户端加固、反调试、代码混淆。
- 物品复制漏洞。

必须强调：关键操作必须服务端权威验证，客户端数据不可作为最终依据。

### 压力 / 弱网测试

重点覆盖：

- 阶梯加压、突发加压、峰值波谷。
- 24-72 小时持续负载。
- 宕机后恢复和优雅降级。
- 2G/3G/4G/5G、WiFi 与蜂窝切换。
- 高延迟、高抖动、丢包、完全断网。
- 频繁断线重连、session 堆积、资源泄漏。

弱网铁律：

- 不能出现收支不等。
- 不能卡死崩溃。
- 核心功能不能受阻。
- 不能损害玩家利益或额外获利。
- 必须有断线重连机制。

## Excel 输出规范

当用户要求生成 Excel 文件时：

- 文件格式：`.xlsx`。
- 文件名：`{系统名称}测试用例.xlsx`。
- Sheet 名称：`{系统名称}测试用例`。
- 第一行为表头，第二行开始填写用例数据。
- 表头：蓝色背景 `#4472C4`、白色加粗字、居中。
- 冻结首行。
- 开启自动筛选。
- 列宽自适应。
- 全单元格加细边框。
- 优先级颜色：高=`#FFC7CE`，中=`#FFEB9C`，低=`#C6EFCE`。
- 操作步骤和预期结果中的多条目用 `\n` 分隔。

## 输出质量要求

- 用例必须可执行，步骤清晰，预期结果可验证。
- 避免空泛描述，如“功能正常”“显示正确”；要写清楚具体状态、数值、文案、奖励、数据变化。
- 不允许重复用例。
- 对核心系统优先覆盖奖励、结算、排行、弱网、并发、跨天、断线重连、数据一致性。
- 如果策划文档信息不足，先基于明确内容生成用例，并标注需要补充确认的规则点。
